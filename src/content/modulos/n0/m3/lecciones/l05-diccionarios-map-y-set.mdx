## Respuesta corta

Un **objeto** usado como diccionario guarda `clave → valor` y se recorre con las mismas claves que ya conoces; `Object.hasOwn` distingue una clave **propia** de una heredada y evita el `NaN` del primer conteo. Un **`Set`** guarda valores **sin repetirlos** y un **`Map`** es la estructura hecha para `get`/`set` por clave. Los tres resuelven lo que `filter` una y otra vez no puede: responder «¿cuántas veces?» y «¿cuánto en total?» en **una sola pasada**.

## Conceptos

### Contar en un objeto: clave → recuento

```js
// resumen-categorias.js — conteos con objeto-diccionario y únicos con Set (lección l05)
export function cuentaPorCategoria(gastos) {
  if (!Array.isArray(gastos)) {
    throw new TypeError("cuentaPorCategoria espera una lista de gastos");
  }
  const cuentas = {};
  for (const gasto of gastos) {
    if (Object.hasOwn(cuentas, gasto.categoria)) {
      cuentas[gasto.categoria] = cuentas[gasto.categoria] + 1;
    } else {
      cuentas[gasto.categoria] = 1;
    }
  }
  return cuentas;
}

export function categoriasUnicas(gastos) {
  if (!Array.isArray(gastos)) {
    throw new TypeError("categoriasUnicas espera una lista de gastos");
  }
  const unicas = new Set();
  for (const gasto of gastos) {
    unicas.add(gasto.categoria);
  }
  return [...unicas].sort();
}

export function importesPorCategoria(gastos) {
  if (!Array.isArray(gastos)) {
    throw new TypeError("importesPorCategoria espera una lista de gastos");
  }
  const acumulados = new Map();
  for (const gasto of gastos) {
    const previo = acumulados.get(gasto.categoria) ?? 0;
    acumulados.set(gasto.categoria, previo + gasto.importe);
  }
  return acumulados;
}
```

`cuentaPorCategoria` recorre la lista **una vez** y va subiendo el contador de cada categoría: `{ comida: 2, ocio: 1 }`. El detalle que importa es `Object.hasOwn`: la primera vez que ves una clave no existe, y escribir `cuentas[cat] + 1` sin comprobar haría `undefined + 1`, que **no lanza** sino que produce `NaN` (verificable con `node -e "console.log(undefined + 1)"`). La rama `else` pone `1` en su lugar.

### `Set`: valores únicos, sin repetir

Para «categorías sin repetir» no hace falta ningún conteo: `unicas.add(...)` simplemente ignora lo que ya está dentro. El `Set` no devuelve una lista, así que la conviertes con `[...unicas]` (spread, l03) y encadenas `.sort()` para un orden estable: `categoriasUnicas(gastos)` → `["comida", "ocio"]`. Con la lista vacía, el `Set` arranca vacío y devuelves `[]`.

Una advertencia sobre lo que **no** deduplica: el `Set` compara valores, y dos objetos nunca son el mismo valor aunque tengan los campos iguales — `new Set([{ a: 1 }, { a: 1 }]).size` es `2`. Para registros duplicados necesitas una clave (`id`, `descripcion`) y una comprobación propia.

### `Map`: get/set con claves bien definidas

`importesPorCategoria` acumula el importe por categoría en un `Map`: `get(clave)` devuelve el acumulado o `undefined` si no existe (y `?? 0` cubre esa primera vez), `set(clave, valor)` guarda, `.size` cuenta. Frente al objeto-diccionario, un `Map` no tiene problema con claves heredadas ni requiere `hasOwn`: si `get` devuelve `undefined`, es que la clave no estaba. Elegir uno u otro es de gustos aquí; el objeto es JSON y literales sencillos, el `Map` es API explícita (`get`/`set`/`has`/`delete`).

## Ejercicio

Crea `ejercicios/principal.js` con una función `categoriaPrincipal(cuentas)`.

Contrato: `cuentas` es un diccionario de recuentos como el que devuelve `cuentaPorCategoria` (por ejemplo `{ comida: 4, ocio: 2 }`). Devuelve el **nombre** de la categoría con más gastos; **en empate, la primera alfabéticamente**.

Esto se cumple cuando:

- `categoriaPrincipal({ comida: 4, ocio: 2 })` devuelve `"comida"`;
- `categoriaPrincipal({ ocio: 2, comida: 2 })` también devuelve `"comida"` (empate → alfabética);
- un diccionario vacío lanza `RangeError` y una entrada que no es diccionario (texto o lista) lanza `TypeError`;
- `node --test ejercicios/principal.test.js` termina en verde con las tres pruebas.

Pista: `Object.keys(cuentas).sort()` te da las claves en orden alfabético; recórrelas y cambia de «mejor» solo si el recuento es **estrictamente mayor**.

## Solución explicada

```js
// principal.js — el ejercicio resuelto (lección l05)
export function categoriaPrincipal(cuentas) {
  if (cuentas === null || typeof cuentas !== "object" || Array.isArray(cuentas)) {
    throw new TypeError("categoriaPrincipal espera un diccionario de recuentos");
  }
  const claves = Object.keys(cuentas).sort();
  if (claves.length === 0) {
    throw new RangeError("categoriaPrincipal necesita al menos una categoría");
  }
  let mejor = claves[0];
  for (const clave of claves) {
    if (cuentas[clave] > cuentas[mejor]) {
      mejor = clave;
    }
  }
  return mejor;
}
```

## Errores comunes

- **Contar sin comprobar la primera vez.** `cuentas[cat] + 1` con clave inexistente da `NaN` para siempre. Usa `Object.hasOwn` (o `?? 0`) antes de sumar.
- **Leer claves heredadas como si fueran tuyas.** `cuentas["toString"]` devuelve una función heredada del prototipo; `Object.hasOwn` la descarta.
- **Esperar que un `Set` deduplique objetos por contenido.** Compara referencias: dos registros iguales cuentan dos. Deduplica por una clave tuya.
- **Acceder a un `Map` como si fuera un objeto.** `acumulados["comida"]` es `undefined` en un `Map`; el camino es `get` y `set`.
- **Devolver el `Set` sin convertir.** Un `Set` no tiene `.sort()` ni índice: primero `[...set]`, después lo que necesites.
