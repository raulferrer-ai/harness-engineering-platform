## Respuesta corta

Un **array** es una lista ordenada de elementos con índice desde `0` y longitud en `.length`. Leer una posición que no existe **no falla**: devuelve `undefined`, y el `TypeError` llega después, cuando algo intenta usarlo. Por eso las funciones del módulo comprueban la entrada con `Array.isArray` y **devuelven listas nuevas** (`[...lista, elemento]`) en lugar de modificar la que recibieron.

## Conceptos

### Una lista, un índice

```js
// gastos.js — crear, ampliar y consultar listas sin mutarlas (lección l03)
export function crearGasto(descripcion, categoria, importe) {
  if (typeof descripcion !== "string" || descripcion.trim() === "") {
    throw new TypeError("crearGasto espera una descripción no vacía");
  }
  if (typeof categoria !== "string" || categoria.trim() === "") {
    throw new TypeError("crearGasto espera una categoría no vacía");
  }
  if (typeof importe !== "number" || Number.isNaN(importe) || importe < 0) {
    throw new TypeError("crearGasto espera un importe numérico no negativo");
  }
  return Object.freeze({ descripcion: descripcion.trim(), categoria: categoria.trim(), importe });
}

export function agregarGasto(gastos, gasto) {
  if (!Array.isArray(gastos)) {
    throw new TypeError("agregarGasto espera una lista de gastos");
  }
  if (gasto === null || typeof gasto !== "object" || !("importe" in gasto)) {
    throw new TypeError("agregarGasto espera un gasto con sus campos");
  }
  return [...gastos, gasto];
}

export function gastoEn(gastos, posicion) {
  if (!Array.isArray(gastos)) {
    throw new TypeError("gastoEn espera una lista de gastos");
  }
  if (!Number.isInteger(posicion) || posicion < 0 || posicion >= gastos.length) {
    throw new RangeError(`posición ${posicion} fuera de la lista (0…${gastos.length - 1})`);
  }
  return gastos[posicion];
}
```

Una lista se lee con `gastos[0]`, `gastos[1]`… y el último índice válido es `gastos.length - 1`. `gastoEn` defiende ese límite **antes** de leer: posición negativa, no entera o `>= length` son `RangeError`, con la ventana válida escrita en el mensaje. Fíjate en que `Array.isArray` es la guarda de lista (otras formas, como `typeof lista === "object"`, también dejan pasar objetos que no son listas).

### Fuera de rango: `undefined`, no una excepción

`gastos[7]` con una lista de un elemento **no lanza**: devuelve `undefined`, porque en JavaScript un array es un objeto y leer una clave inexistente devuelve «nada». El error llega en la línea siguiente, al usar ese `undefined`. El fichero de error del módulo lo demuestra:

```js
// errores/fuera-de-rango.js — acceder fuera de la lista devuelve undefined y revienta después (lección l03)
const gastos = [{ descripcion: "café", importe: 2.5 }];
const inexistente = gastos[7];
console.log(inexistente.importe);
```

Salida real, ejecutada el 2026-10-21 con Node v24.22.0 (tras la cabecera con la ruta del fichero):

```text
TypeError: Cannot read properties of undefined (reading 'importe')
código=1
```

Termina en rojo con código `1`. La defensa es comprobar el acceso como hace `gastoEn`, o comprobar el resultado con `=== undefined` antes de usarlo.

### Listas nuevas en vez de mutar

`agregarGasto` no hace `gastos.push(gasto)`: devuelve `[...gastos, gasto]`, una lista **nueva** con el mismo contenido más el gasto. `[...gastos]` copia los elementos (spread) y deja la original intacta. Dos razones: quien llama no espera que su lista cambie a sus espaldas, y una lista devuelta puede seguir siendo `const`. `crearGasto` va en la misma línea defensiva: `Object.freeze` sobre el registro, el patrón que ya usabas en [l06 de m2](/curriculo/n0/m2/l06-objetos-como-modelos/).

## Ejercicio

Crea `ejercicios/insertar.js` con una función `insertarAlPrincipio(gastos, gasto)`.

Contrato: `gastos` es una lista y `gasto` es un registro (objeto). Devuelve una lista **nueva** con el gasto en la posición `0` y todos los anteriores detrás, sin tocar la lista original.

Esto se cumple cuando:

- dado `lista = [{ importe: 1 }]`, `insertarAlPrincipio(lista, { importe: 9 })` devuelve una lista de 2 cuyo primer elemento es el gasto nuevo, y `lista.length` sigue siendo `1`;
- una lista que no es lista lanza `TypeError` y un `gasto` que no es objeto lanza `TypeError`;
- `node --test ejercicios/insertar.test.js` termina en verde con las dos pruebas.

Pista: la lista nueva es literalmente `[gasto, ...gastos]`.

## Solución explicada

```js
// insertar.js — el ejercicio resuelto (lección l03)
export function insertarAlPrincipio(gastos, gasto) {
  if (!Array.isArray(gastos)) {
    throw new TypeError("insertarAlPrincipio espera una lista de gastos");
  }
  if (gasto === null || typeof gasto !== "object") {
    throw new TypeError("insertarAlPrincipio espera un gasto");
  }
  return [gasto, ...gastos];
}
```

Salida real de `node --test insertar.test.js`, ejecutada el 2026-10-21 con Node v24.22.0:

```text
✔ coloca el gasto al principio sin mutar la lista (0.753666ms)
✔ valida lista y gasto (0.243125ms)
ℹ tests 2
ℹ pass 2
ℹ fail 0
```

La primera prueba es la que importa: mide la lista **de entrada** después de la llamada (`length` sigue en `1`) y la de **salida** (`length` 2). Si la solución hiciera `gastos.unshift(gasto)`, la aserción `lista.length === 1` recibiría `2` y el rojo te lo diría — es exactamente el fallo registrado en «Cómo verificarlo».

## Errores comunes

- **Confiar en que leer fuera de rango lanza.** Devuelve `undefined`; el `TypeError` aparece en otra línea, lejos del culpable. Comprueba el acceso o el resultado.
- **Comparar listas con `===`.** Compara referencias, no contenido: dos literales idénticos (`[1] === [1]`) son `false`. Para contenido usa `assert.deepStrictEqual` en las pruebas.
- **Mutar la lista de entrada «para simplificar».** `push`/`unshift` sobre la lista que entró cambia el estado de quien te la pasó; es el rojo del paso 3. Devuelve una lista nueva.
- **Olvidar que `typeof []` es `"object"`.** No sirve para distinguir listas: usa `Array.isArray`.
- **Escribir índices desde `1`.** Los arrays empiezan en `0`: `gastos[1]` es el segundo gasto, y el primero es `gastos[0]`.
